Review operator default grants and effective client memberships before approval. Keep the export outside Git with owner-only permissions and record its checksum.

After approval, execute the exact tested Migration 06 file once, from BEGIN through COMMIT. Its SHA-256 is `e3deb2268ed16a440cbfa0895a13d1c5dbb140aa041e39b2dbe589defd0dcc7c`. Stop and inspect the catalog if the result is ambiguous. Run the consolidated postflight and compare it with the preflight. Expect the owner-only SELECT policy, no ordinary client writes or anonymous access, a security-invoker view, two new authenticated RPCs with empty search paths and anonymous execution denied, validated foreign keys and primary key, and valid preference and pair indexes. Compare existing RPC definitions and data counts, accounting for concurrent activity. The preference table begins empty.

Migration 10 already applies the caller's hide cursor in the inbox before pagination. Hide and send lock the same conversation row. A send committed ahead of hide is covered by its cursor. A send committed after hide makes the thread visible again. Opening through a profile leaves visibility and any existing read-cursor behavior independent.

SwiftUI should keep the compact list and the existing `chat_threads` inbox route. Fetch mute state with the signed-in student's RLS-scoped preference query because the RPC response does not include mute state. Mute stores a preference, and the current messaging migrations do not implement chat notification suppression.

Rollback before COMMIT is transactional. After commit, pause the client actions and revoke their execution through a separately approved operation if needed. Keep the preference table in place to preserve hides. Export the preference rows privately and verify their checksum before any removal.
