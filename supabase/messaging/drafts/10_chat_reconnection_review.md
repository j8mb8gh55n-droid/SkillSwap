# Migration 10 reconnection review

Migration 10 depends on deployed Migrations 05 and 07. Migration 06 is optional. When its preference table exists, the inbox read applies the caller's hide cursor before pagination. The profile route can still open the thread. A newer message restores inbox visibility under the same cursor rule, including a reconnection message.

The allowance is lifetime per conversation. The final block remover receives the allowance. The server records it as spent when the reconnection message is written. An existing declined thread has no reliable final unblock owner. Its history is visible without retroactive eligibility. Read-only inbox visibility includes any declined or blocked thread with stored messages, even when the original introduction was declined. This preserves history for older threads whose block history cannot be distinguished from original declines.

The read API scopes every result to a participant and returns only the caller's eligibility, the pending request direction and ID, limited profile fields, and the latest message. Older clients can read history through their existing profile route. Their original response RPC rejects pending reconnections. Ship the SwiftUI update with the migration so recipients can use the reconnection response RPC. Test the hosted PostgREST JSON response and both app versions in staging before enabling the feature.

Before deployment, verify the current block, unblock and response functions and grants, the unique pair index, conversation and message RLS, and the absence of the new table and RPCs. Capture the replaced definitions and grants privately with aggregate history counts. Compare the postflight with that capture and verify the new ACLs and constraints. The migration is transactional. After use, preserve the allowance ledger and message history. Disable new reconnects before rollback, and resolve pending reconnect requests to a read-only state before restoring the original response function. Restoring that function while a reconnection is pending could give the wrong participant approval authority.

Run the existing Migration 05 regression suite in an empty network-disabled PostgreSQL container. Then run test_reconnection_local.py against the same disposable container from the repository root. It applies 07 and 10 locally, exercises lifecycle and lock waits, and applies 06 locally to test future inbox visibility.
